# 反馈与本机诊断

设置 → 反馈与帮助提供三个入口：

- Telegram：https://t.me/moyubotnya
- QQ 交流群：2162036353，点击复制群号后在 QQ 搜索加入。
- GitHub：https://github.com/whitemoono/moyubot/issues

页面可填写问题、复现步骤与期望结果，并生成带应用版本、系统、工作区类型和当前模型的反馈草稿。用户可以编辑完整预览、复制到群组，或点击「GitHub 提交 Issue」：先复制草稿，再打开仓库的新建 Issue 页面。正文不进入链接查询参数；用户自行粘贴并提交。应用不自动发送群消息或创建 Issue。

诊断记录从此功能启用后开始收集，保存在本机数据目录的 `diagnostics.json`。记录 Bot 工具失败及失败命令、模型调用错误、终端非零退出或超时、IPC 操作异常、云电脑告警、主进程异常与界面进程退出。用户主动停止、拒绝执行不作为失败命令收集。成功命令输出与完整聊天不被诊断功能额外保存。

最多保留近 7 天的 60 条，每条限制内容长度；启动、读取和新增时淘汰过期记录。页面展示最近 10 条供勾选，默认不附带报错，失败命令需要额外勾选。支持刷新与清空。

写入前会过滤当前保存的密钥、常见凭证字段、认证头、私钥、链接的查询参数及片段、用户目录名与邮箱。读取时再次过滤，覆盖之后才保存的新凭证。自动脱敏是尽力处理，业务信息及非标准格式的秘密仍可能存在，因此发送内容可编辑并提示用户检查。无诊断上传服务或自动遥测。

验证：`node --test scripts/diagnostics.test.cjs`；构建后运行 `pnpm --filter @moyu/desktop exec electron --no-sandbox ../../scripts/feedback-smoke.cjs`。后者使用隔离数据，拦截剪贴板与外部链接，验证记录、勾选、脱敏、预览、复制、Issue 入口及清空，不提交外部反馈。
