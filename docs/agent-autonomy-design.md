# moyubot 自主智能体：整体设计与优化方案

> 目标：把现有散件（runLoop / todo / goal / spawn / workflow / plan / 预算 / 修剪）串成一套**可控的自主执行体系**，回答"能不能自己规划、拆任务、跑到底、可监督"。

## 0. 现状体检（基于代码事实）

| 机制 | 现状 | 文件/常量 |
| --- | --- | --- |
| 单轮循环 | 模型驱动多步，直到给出无工具调用的回复为止 | `agent.ts runLoop`；`maxSteps=32`（可调 1–200）、累计生成 131072、时长 1200s |
| 任务清单 | 有 `todo_write`，整体替换式，注入系统提示 | `store.writeTodos` |
| 跨轮目标 | 有 `set_goal`，但**无自动续跑**（用户当初明确关掉） | `goalPrompt` 每步注入 |
| 子代理 | 只读、可续聊、可 fork、并行≤4、深度≤2 | `childBotFor`、`SUBAGENT_*` |
| 编排脚本 | `run_script` vm 沙箱 fan-out/pipeline | `workflow.ts` |
| 计划模式 | `exit_plan_mode` 强制人工批准，独立于 approvalPolicy | 设计如此 |
| 上下文 | 预算修剪阶梯 + 摘要压缩 + 工具描述瘦身 | `context.ts` |
| 预算 | 父子**共享**同一个 TaskOutputBudget | `runLoop` 透传 |
| 完成判定 | 模型自称完成即结束，**无校验步** | 现有告警文字提示别乱说完成 |

**核心缺口**：自主性只有"单轮内"和"人工批准"两级，缺"跨轮续航 + 停止条件 + 完成校验 + 统一监督视图"。散件都在，缺把它们连成闭环的**编排层**，以及"到底跑不跑、跑几轮、怎么算完成"的**策略层**。

## 1. 设计：三级自主阶梯（Autonomy Ladder）

按用户可控度从低到高，一个 Bot 选一级：

```
L0 手动    每步/写操作都要批准（approvalPolicy=ask）—— 现状保守档
L1 轮内自动 一轮内自主多步（现状 approvalPolicy≠ask），结束即交回
L2 目标续航  立一个 goal 后，框架自动"再来一轮"直到 goal 达成或触顶
```

- **新增 L2 = 你上次问的"自动跑到底"**，但要带**护栏**（否则最危险）：
  - 最大轮数上限（默认 8，可配）；每轮 = 一次现有 runLoop
  - 停止条件三选一即停：① 模型 `update_goal complete`；② 触发 blocked；③ 累计预算（token/时长/轮数）耗尽
  - 任一轮**报错即停**，不无限重试（沿用现有 run_end error）
  - L2 默认**不跨"计划批准"**：计划模式仍人工批准，批准的执行阶段才续航
- 触发方式：不是 Bot 常驻开关，而是**每个 goal 携带 autonomy 字段**（`'turn' | 'until_done'`），UI 在设定目标时选。避免"这个 Bot 永远自己转"失控。

## 2. 设计：规划 → 拆分 → 执行 → 校验 闭环（编排层）

现在这些能力是"模型想用才用"。优化=给**结构**而非强制：

```
set_goal(objective, autonomy)
   └─ 若任务复杂 → 引导模型先 todo_write 出可执行分解（≤N 步，每步可验收）
        └─ 逐步推进：独立调研 → spawn_agent 并行；多阶段 → run_script
             └─ 每步完成 → 勾 todo + （可选）自检：重读产物/跑校验命令
                  └─ 全部完成 → update_goal complete；否则 blocked 写清卡点
```

关键改进点：

1. **"完成校验"步**（现在完全没有）：goal 标 complete 前，若声明了验收条件（`goal.successCriteria[]`），框架要求模型逐条对照证据（文件/命令输出/URL），缺证据不许 complete。→ 把"别乱说完成"从一句提示变成**机制**。
2. **todo 与 goal 绑定**：goal 的 successCriteria 直接来自 todo 分解，勾满才算达标，进度可视。
3. **拆分的引导文案**（可选开关"自主规划"）：只在 L1/L2 注入"多步先 todo、独立项 spawn 并行"的引导；纯闲聊不注入，避免 over-plan。

## 3. 设计：预算与安全护栏

| 风险 | 优化 |
| --- | --- |
| 父子共享一个 TaskOutputBudget，坏孩子抽干爸爸 | 给**子代理独立子预算**（父分配 quota，用完只停子不停父）；或至少记录归属 |
| L2 无限转 | 轮数 + token + 墙钟三重上限；每轮 checkpoint，可中断/可续 |
| 子代理只读是对的，但复杂任务想让它能写 | 保持只读为默认；新增 **worker-with-write**：写操作**回父会话审批**（不在子线程放行），approvalPolicy 只在父生效 |
| 工具太多撑爆小窗 | 已做描述瘦身阶梯；再加**按任务动态裁剪工具面**（调研任务不下发 install_*/schedule） |
| 计划模式绕过 | exit_plan_mode 恒人工批准（现状保持） |

## 4. 设计：统一监督视图（UI）

现在"在跑什么"散在 job_list / 子代理卡片 / 目标 chip。优化=一个**运行视图**：

- 侧栏新增「活动」入口（或复用右侧栏"详情"）：
  - 当前 goal（objective + autonomy + successCriteria 勾选进度 + 已用轮数/预算）
  - 在跑任务列表（来自 `job_list`/`listSubagents`）：可逐个 `job_kill`、可钻取子代理续聊
  - 时间线：本轮跑了哪些工具、每步耗时/token
- 长任务（L2）有**进度可见性**是采纳它的前提。

## 5. 与 DSH 的差异与借鉴（务实）

- DSH 的 goal 有 `max_goal_rounds` 自动续跑——对应我们的 L2，**必须带同样的轮数上限**（这正是"要不要自动跑"的答案：要，但有顶）。
- DSH 的 compaction/pruning/workflow/subagent 我们已对齐并加了中文语义与只读子代理约束。
- DSH 的 plan mode 人工闸——我们保持，且 L2 不绕过它。

## 6. 实施优先级（建议）

| 顺序 | 项 | 价值 | 改动量 |
| --- | --- | --- | --- |
| P1 | **goal.successCriteria + 完成校验 + todo 绑定** | 把"别乱说完成"变成机制，收益最大风险最低 | 中（store/goal + 一处 runLoop 校验） |
| P2 | **L2 目标续航（带三重上限）** | 你要的"自动跑到底"，闭环成型 | 中（runtime 外层 while + 停止条件） |
| P3 | **运行监督视图** | L2 可用的前提，透明可控 | 中（UI，复用现有 IPC） |
| P4 | **子代理独立预算 + worker-with-write 回父审批** | 复杂任务编排安全 | 中偏大 |
| P5 | 动态工具面裁剪 | 小窗/成本优化 | 小 |

> 不建议一次全上。P1 先行：它让"自主"变得**可信**（有验收），P2 再让"自主"变得**可行**（能续航），P3 让"自主"**可控**（看得见、能停）。

## 7. 需要你拍板的取舍

1. L2 续航默认最大轮数（建议 8）？到顶后行为（标 blocked 停下，还是问用户"继续吗"）？
2. worker-with-write：要不要放开"子代理可写、但写操作弹回父审批"？还是坚持子代理纯只读？
3. 自主规划引导：默认开还是做成 Bot 开关（我建议**开关**，纯聊天不该被推去拆任务）。
