# 长期记忆设计

状态：2026-10-29。本文区分已实现界面和下一阶段的记忆引擎方案。

## 产品目标

让每个 Bot 持续了解用户的偏好、长期项目和重要约定。用户能随时查看、纠正和删除；系统能解释一条记忆从哪里来、什么时候更新、为什么用于当前回答。

## 三层上下文

| 层次 | 保存内容 | 使用方式 |
| --- | --- | --- |
| 原始聊天 | 完整消息、工具结果、引用与附件 | 本地保留，作为可追溯来源 |
| 对话摘要 | 当前目标、进度、决定、错误、待办 | 压缩较早历史，继续同一对话 |
| 长期记忆 | 稳定偏好、长期项目、重要约定、持久环境事实 | 按范围与相关度选入回答上下文 |

一次性请求和未确认推测不进入长期记忆。临时进度留在摘要，提醒交给定时任务。凭据不进入记忆。

私聊按 Bot ID 隔离，群聊按群会话 ID 隔离。群成员共享本群记忆，不能召回成员的私聊记忆。共享个人资料仍由设置独立管理，优先于旧记忆中的同类资料；不把 Bot 记忆自动升级为全局记忆。

## 写入和整理：目标方案

1. 用户手动添加或明确要求“记住”时立即记录。保留主动记录这一来源；现有 `manual` 同时包含界面添加和工具写入，旧数据不能可靠细分。
2. 自动整理在上下文压缩时运行；后续增加独立的增量检查点，建议累计 8 轮完整对话且新增文本达到 2,000 字后，在当前回复结束后整理一次，避免短对话一直没有机会沉淀记忆。检查点按会话持久化，重启不重复提取；不在每轮回复上增加额外请求。
3. 提取候选记忆时附上来源消息 ID、类别、主题键、事实文本。只接纳来源中能直接支持的事实。历史和记忆均作为资料，不能成为提取器的操作指令。
4. 同一范围先做文本归一化查重，再按主题比较事实。重复确认只更新确认时间；同一事实的新值替代旧版本，例如“默认用 Python”改成“这个项目默认用 TypeScript”。不同项目的偏好用主题区分。
5. 用户手动纠正优先于自动提取。时间较新但证据含糊的矛盾事实先标记待确认，不自动覆盖。版本关系与修改来源保留，可恢复上个版本。
6. 一次整理的候选、版本变化、整理批次和检查点用单次原子提交写入。模型返回无效、中断或写盘失败不推进检查点、不发布半批记忆。
7. 后台整理失败保留上一份有效记忆，不阻塞已完成的聊天；上下文压缩本身失败继续沿用当前报错和历史保留机制。模型调用需要统计用量。

自动和主动写入都应在存储入口执行凭据过滤。模型的保密提示与正则只能作为补充，不能视为完整识别能力。

## 数据模型：增量演进

现有 `memories.json` 可以继续使用，无需立即引入数据库。增加可选字段兼容旧数据，达到大规模检索或事务复杂度后再迁移 SQLite。

| 字段 | 用途 |
| --- | --- |
| `id`, `scopeId`, `scopeType` | 记忆标识、Bot / 群聊范围；旧 `botId` 兼容映射 |
| `text`, `category`, `topicKey` | 独立事实、偏好 / 项目 / 约定 / 环境、同一事实的归并键 |
| `source`, `sourceMessageIds` | 手动添加 / 用户要求 / 自动整理、原文证据 |
| `createdAt`, `updatedAt`, `confirmedAt` | 首次记录、内容修改、重复确认时间 |
| `batchId` | 产生实际新增或修改的整理批次 |
| `pinned`, `status` | 固定、有效 / 已替代 / 待确认 |
| `supersedesId`, `revision` | 版本与替代关系 |
| `lastUsedAt`, `useCount` | 召回记录，用于优化排序，不能当作事实可信度 |

整理批次单独保存范围、时间、覆盖的消息边界、新增 / 更新 / 失效的记忆 ID。没有实质变化的整理不把所有旧记忆重新顶到“最近整理”。

用户删除时同步清除检索索引，并保存最小必要的忽略标记（范围、来源消息 ID、归一化指纹），避免后台重复扫描原消息又把它恢复。用户明确要求重新记录时解除忽略。删除长期记忆不会删除原始聊天或摘要，界面需清楚说明；彻底清除某个事实还需处理这些原始来源。

## 召回：目标方案

每次回复取“固定且有效的记忆 + 与本次问题相关的有效记忆”，用 Token 预算控制长度，而非单纯截取 24 条。建议初始预算为上下文窗口的 8%，上限 2,400 Token；固定记忆也占预算，超过时明确提示调整。

第一阶段使用中文分词 / 字符片段、关键词、类别和项目主题匹配，结合更新时效排序。第二阶段按需要增加向量索引，与关键词结果合并；向量模型和索引都可重建，原始事实仍是主数据。任何检索都先限制范围。

同一事实只注入当前有效版本。记忆用资料块包装，明确当前用户指示优先，不允许记忆中的文本升级为系统指令。`recall` 继续提供显式检索，帮助模型查找没有自动选入的内容。

## 本次已实现的界面

- 右侧“资料库 → 长期记忆”只预览最近新增的 3 条，按创建时间倒序，不受是否固定影响。同毫秒的记录按后写入优先；点击整张卡片进入小窗。
- 卡片显示“最近整理”、来源和相对时间，以及“查看全部 N 条记忆”。空状态仍可打开记忆库。
- 小窗标题为“Bot 名称的记忆”，只显示该 Bot 的记忆，支持全文关键词筛选、手动添加、删除，展示来源、记录时间和固定标记。搜索不会改变卡片预览。
- 小窗约 480px 宽、限制最大高度，列表滚动；支持 Esc、遮罩关闭和键盘焦点约束，适配明暗主题与窄窗口。
- 整理成功和 `remember` 工具成功后立即刷新。切换 Bot 时关闭小窗并清空草稿和搜索；延迟返回的旧 Bot 数据不覆盖新 Bot。

目前没有 `updatedAt` 或 `batchId`，因此“最近整理”按实际新写入时间展示，包含主动记录和自动整理，并标明来源。旧条目重复命中不会重新置顶。实现批次与版本后，改成按实际内容变动时间排序，展示最近发生变化的 3 条，仍不要求它们来自同一批次。

## 实施顺序与验收

1. 本次：最近 3 条预览、完整记忆小窗、搜索 / 添加 / 删除、实时刷新、Bot 隔离。
2. 下一步：存储入口校验、来源消息与批次、手动编辑 / 固定、版本替换、删除忽略标记、原子提交。验证重复整理幂等、冲突优先级、中断恢复和旧数据兼容。
3. 然后：独立增量整理、受预算限制的相关召回，最后按实际数据量决定是否引入向量检索。验证中文召回、跨范围隔离、上下文预算和调用成本。

界面验收使用独立 Electron 数据运行 `scripts/desktop-smoke.cjs --memories-only`，覆盖预览限制与顺序、全部记录与长文本、搜索、写入与删除落盘、记忆事件刷新、切换 Bot、重启持久化、键盘与明暗 / 窄窗布局。
